From Vulnerability to Compliance: Securing Legacy and Cloud Systems at HanTech

TS Academy Cybersecurity Capstone | Group 95

Project Overview

This project explores how organisations can identify, assess and manage cybersecurity risks across legacy systems and cloud environments.

Using a fictional technology company, HanTech, as the case study, our team conducted a vulnerability assessment of a Metasploitable2 lab environment.

The assessment focused on identifying security weaknesses, evaluating their potential business impact, and recommending practical security controls and governance policies.

The goal was to go beyond identifying vulnerabilities and understand how technical weaknesses can create organisational risks.

Project Objectives

- Identify five vulnerabilities in the Metasploitable2 environment.
- Examine affected services and potential attacker objectives.
- Assess likelihood, impact and overall risk.
- Reference relevant CVEs and CVSS scores where applicable.
- Recommend security controls and mitigation strategies.
- Develop Governance, Risk and Compliance (GRC) policy recommendations.
- Explain cloud security fundamentals and shared responsibility.

Project Scope

1. Vulnerability Assessment

The project examined five security findings identified during the lab assessment.

Each finding was documented with its affected service, technical description, potential attacker objective and supporting evidence.

2. Risk Assessment

The identified vulnerabilities were evaluated based on:

- Likelihood of exploitation
- Potential impact
- Overall risk rating
- Relevant CVE and CVSS information
- Supporting technical evidence

3. Security Controls

The project recommended security measures to reduce identified risks, including:

- Strong authentication and access management
- System hardening
- Patch management
- Network security and segmentation
- Vulnerability monitoring
- Least-privilege access

4. Governance, Risk and Compliance

The GRC section explored organisational policies that support effective cybersecurity management, including:

- Access Control Policy
- Password Policy
- Patch Management Policy
- Vulnerability Management Policy

5. Cloud Security

The project also examined:

- Cloud shared responsibility model
- Identity and Access Management (IAM)
- Authentication, authorisation and auditing
- Multi-Factor Authentication (MFA)
- Least privilege
- Cloud misconfiguration and weak credentials
- Data protection and encryption
- Cloud security best practices

Tools and Technologies

The practical assessment involved cybersecurity tools and a virtual lab environment, including:

- Kali Linux
- Metasploitable2
- Nmap
- Metasploit Framework
- Netcat
- VirtualBox

Key Learning Outcomes

This project strengthened my understanding of:

1. Vulnerability identification and assessment.
2. Network service enumeration.
3. Practical security testing and evidence collection.
4. CVE and CVSS interpretation.
5. Risk assessment and business impact analysis.
6. Security controls and remediation planning.
7. Governance, Risk and Compliance principles.
8. Cloud security fundamentals.
9. Technical documentation and teamwork.

Project Approach

The assessment followed a structured process:

1. Identify exposed services and potential weaknesses.
2. Investigate and validate findings within the authorised lab.
3. Document technical evidence.
4. Evaluate likelihood and potential business impact.
5. Recommend security controls.
6. Connect technical findings to organisational policies and cloud security practices.

Lab Safety and Ethical Considerations

All practical testing was conducted for educational purposes against an intentionally vulnerable training environment.

The project emphasises authorised security testing, responsible evidence handling, risk assessment and appropriate remediation.
